# SDK 0.3 pin and isolated testnet E2E gate design

## Objective and selected approach

Pin the private Platform to the exact public `@perkos/agent-sdk@0.3.0` release and prepare the
controlled testnet end-to-end validation without changing the live quote-only boundary. Three
approaches were considered: run the E2E against the current 0.2 verifier, temporarily enable the
public production API, or ship a traceable dependency-only release and exercise it in an isolated
VPS environment. The third approach is selected because it tests the exact release intended for
operation while keeping public routes, production data and merchant delivery unavailable.

Platform 0.4.1 changes only release metadata, the pinned SDK package and the verifier evidence
recorded with a settlement. The package integrity is fixed to the npm registry value reviewed at
release time. Existing transaction parsing, reservation, broadcast, reconciliation and delivery
logic is unchanged. Tests must prove that a reserved settlement records SDK 0.3.0 and the checksum
derived from its exact registry integrity.

## Isolated execution boundary

The candidate image is built only on the PerkOS VPS from the reviewed merge. The first deployment
remains quote-only and must pass the existing migration, health, readiness, discovery and rollback
checks. A separate temporary E2E stack then uses its own PostgreSQL database, Docker network,
merchant record and testnet-only route. It is not attached to Caddy, publishes no host port and
cannot access production merchant credentials or delivery state.

Only a pre-funded, capped testnet payer may sign. Leather or an independently controlled signer
must receive the canonical unsigned transaction; the SDK and Platform do not receive or persist a
private key. The run permits one quote, one signed transaction and one broadcast attempt. Fee,
asset, amount, recipient, origin, merchant and quote-lifetime limits remain explicit and
fail-closed. Sponsorship and mainnet are prohibited.

## Success, failure and evidence

Success requires quote issuance, local signed-transaction verification, one durable reservation,
one testnet broadcast, canonical confirmation at the configured depth, one signed receipt and an
idempotent delivery-ledger claim/complete cycle. Retrying settle must return the existing record
without rebroadcast. Evidence is written outside GitHub and excludes credentials, private keys,
signed raw transaction bytes and reusable tokens.

Any dependency-integrity mismatch, unexpected txid, ambiguous broadcast, failed confirmation,
restart, duplicate reservation, receipt mismatch or delivery conflict stops the run. Ambiguous
transactions remain pending for observation and are never blindly rebroadcast. The isolated stack
is removed after evidence capture; the production deployment remains quote-only. Enabling public
verify, settlement, reconciliation or delivery requires a later explicit, reversible rollout and
does not follow automatically from a successful E2E.
